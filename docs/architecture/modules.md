# Module boundaries

| Module | Responsibility | Main routes |
|---|---|---|
| Identity | Development-only demo identity, profile, goals | `/me`, `/me/profile`, `/me/goals` |
| Assistant | Read-only daily context, isolated DeepSeek provider, transient short answers and reports | `/assistant/ask`, `/assistant/daily-report` |
| Catalog | Sourced real-place directory and external discussion notes; separate fictional meals and illustrative nutrition | `/venues`, `/external-notes`, `/menu-items` |
| Workouts | Sourced exercise library, training profile, stage-aware plan and confirmed session | `/exercises`, `/me/workout-profile`, `/workouts/recommend`, `/workouts/sessions` |
| Recommendations | Restriction filtering, rule ranking, job/run persistence, optional explanation wording | `/recommendations/jobs`, `/recommendations/meals` |
| Tracking | Planned decisions, confirmed menu snapshots, photo recognition, USDA-backed nutrition estimates, reviewed records and daily totals | `/decisions`, `/meal-logs`, `/meals/analyze-photo`, `/photo-meals`, `/me/daily-summary` |
| Community | Owned confirmed-meal posts, comments, likes, reports and demo moderation | `/community/posts`, `/community/reports` |
| Habits and rewards | Daily capped habit events, streak/weekly progress, append-only credit ledger and demo badge redemption | `/rewards/overview`, `/rewards/{id}/redeem` |
| Worker | Claim jobs, process recommendations, log status | `python -m apps.api.worker` |
| Web and client | Five primary destinations, reward/profile utilities, floating coach, Progress report, generated API types | `apps/web`, `packages/api-client` |

Domain code lives in `apps/api/modules`. HTTP handlers validate and delegate; services own workflows; models represent persistence. The meal and workout selection engines have no HTTP, SQL, model-provider or merchant-payment dependency. Community references the authoritative menu meal log; it cannot edit confirmed intake or catalog values. Tracking, Community and Workouts award eligible Habit events in their own database transaction; neither recommendation clicks nor likes/comments award credits. Photo analysis calls OpenRouter from the active Tracking module and returns a draft requiring review; image bytes are not persisted.

The assistant is a provider-facing boundary, not a domain authority. Its context builder is read-only and uses confirmed menu logs, saved photo-review rows with status, and completed workouts from the current Hong Kong-local day plus the profile/goal and workout-profile allowlist described in the [architecture overview](overview.md). Pending/processing/failed photo rows are status-only; `not_requested` and `completed` rows count toward the confirmed meal count, and only their `complete` nutrition snapshots contribute to aggregate nutrition. Partial snapshots remain visible per row as matched-food estimates without being represented as aggregate intake. The context excludes image content and paths, review attempt logs/errors, identity/display names, Community data, payments, secrets, and conversation history. The `DeepSeekChatProvider` validates the required key, base URL, model, and timeout before its one Chat Completions request per action with `deepseek-chat`, no streaming, and no automatic retry. The service validates responses and maps configuration to 503, timeout to 504, and upstream/invalid content to 502. Questions, health context, generated content, raw provider bodies, Authorization headers, and API keys are not logged.

Assistant answers and reports are not persisted; no model or migration exists. The floating **Coach** ring is mounted globally in the app shell and keeps only one current exchange in local component state. **Progress** owns the full report and clears it on navigation/unmount. Model output is plain text for the browser and cannot change ranking, workout choice, nutrition snapshots, credits, or Community state. DeepSeek has independent settings and no OpenRouter dependency; the existing OpenRouter explanation and photo flows remain unchanged. The historical starter services and Week 4 image/diet draft adapters under `services/` remain outside the active product path.
